End-to-end latency is not the same as an offset between BGM/accompaniment and Vocal. The OBS source, virtual output, and Full Output recording all receive the shared formal-Mix timeline first. A calculated mic → stream value and the OBS marker in the same row are two observation points in one run and must not be added together. The marker already covers formal Program/Mix alignment → OBS reception; it does not start at the analog ADC or camera image. OBS, a virtual device, and video capture may then add common downstream latency. The OBS and VB-CABLE transport rows are historical evidence from different runs and must not be subtracted as an A/B test. An earlier 1,800-second connector run measured 27.05／40.74／47.86 ms min／avg／max with zero continuity faults; public guidance uses the newer 600-second strict gate.

General recommendation: start with the interface manufacturer's ASIO driver at 128 frames and the app at 256 frames. Keep it when the Full check and real singing are stable; raise the app to 512 after underruns, audible crackles, or device recovery. With Windows Audio, prioritize stable formal output and accept higher software-monitor latency. Use hardware Direct Monitor for the singing voice, inspect the app health details, and record a clap／mouth-sync video on the actual streaming setup.
